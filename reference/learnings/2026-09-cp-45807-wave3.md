# CP-45807 wave 3 learnings

Source: `sessions/CP-45807/wave3-learnings.md` (17 dated entries) and
`sessions/CP-45807/2026-09-08_wave3-summary.md` from a consumer repo's Gorkhali
session, condensed to rules. The worktree procedure, the messaging rule, and the
design-fidelity Surveyor guidance below are folded into `commands/execute.md`,
`reference/agents.md`, `commands/verify.md`, `commands/visual.md`, and
`agents/surveyor.md`; this file is the durable record of why.

- Address a running agent by its suffixed spawn name, never the bare roster name —
  a bare name can resume a stale agent from an earlier wave and hand it a
  destructive instruction meant for the current one.
- Every destructive instruction sent to a live agent must state which process or
  checkout it owns, so a wrong recipient can recognize the mismatch and refuse.
- A human and an engineer must never share one writable checkout: a `pnpm install`
  run mid-task while an engineer owned the checkout flipped the lockfile layout and
  raced the browser cache. Dependency tasks (anything touching `package.json`) run
  alone in the main checkout, and the human is told it is locked for the duration.
- Pin `playwright` and `@playwright/test` together; a manual edit to one mid-task
  drifted them apart against a time-locked registry mirror.
- Give every worktree a real `node_modules` via an APFS clone (`cp -cR`, ~11s for
  400MB) instead of a symlink. A symlinked `node_modules` breaks vitest browser mode
  and Storybook's interaction runner for every story, because the addon resolves
  its setup-file URL from the symlink's real path, which falls outside the
  worktree's root. This looked like a race at first; it is structural.
- Never let an engineer mark a task done with untested play tests. When the runner
  is broken in a worktree, Chief fixes the environment first, then the engineer
  verifies.
- Chief must never end a Bash command with its cwd inside a worktree — the harness
  then treats the whole session as worktree-isolated and refuses git against the
  main checkout, merges included. Always `git -C <abs path>` from the repo root.
- Engineers must not call `EnterWorktree` themselves. It re-binds the parent Chief
  session to that worktree on every turn and blocks Chief's git access (surviving
  even `ExitWorktree(keep)`) until the agent goes idle, which stalls merges of every
  other branch while it runs. Create every worktree before spawning any engineer
  instead, and point each engineer at its path in the prompt.
- A subagent spawned after Chief creates a new worktree can get sandboxed to the
  most recently created worktree rather than the one named in its own prompt; it
  must re-point itself with an explicit path rather than retry blind.
- Treat the design bundle as a measurable spec, not just a screenshot: play tests
  prove behavior, not measurement. Run a Surveyor browser pass after every visual
  wave and again after integration, and have Inspector assert computed styles for
  ladder-driven components and rendered widths for integration screens.
- Treat Surveyor findings as hypotheses the owning engineer must confirm or
  disprove by measurement — two of six pass-1 findings in this wave were
  misattributed measurements. Close every dispute with a play assertion in the test
  file, not a chat debate.
- Set the browser viewport explicitly for any Surveyor pass; `agent-browser`
  defaults to 1440x900, which will not match a design built at a different
  viewport (this wave's confirmation pass used a true 1920x1080).
- A consumer task that hits a defect in a file it does not own should stop and
  report rather than patch across ownership. The owner fixes at the source in a
  `*-fix` worktree; the consumer merges the feature branch into its own branch and
  re-verifies.
- Integration tasks need a screen-level layout assertion (rendered widths), not
  only behavior assertions — 154 green play tests, six per-task Inspectors, and an
  engineer self-review all missed a critical layout collapse that a Surveyor
  browser pass caught after integration.
- A play test must interact the way a real user does (mousedown and click on the
  real target); a passing test that contradicts a direct browser observation is
  itself a defect, not a false alarm.
- The Surveyor cannot write its own `agent-records/<name>.json` stub — a
  routing-gate hook blocks it. Chief records Surveyor's return in the stub; the
  Surveyor's own artifacts are `result.json` and its screenshots.
- The standalone design HTML may not render its main pane offline if it fetches a
  website bundle; use the hosted Claude Design artifact or a local static server
  for side-by-side comparison instead.
