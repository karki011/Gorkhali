Wave 5 Spec — Supervision, Provenance, Project Modes

Sourced from firstmate + no-mistakes source studies · 2026-07-02 · Subash Karki · companion to axi-port-plan.html
Headline reframe — firstmate's blocking zero-token watcher cannot port. Its lead is a persistent process that sleeps on a bash watcher; phantom's Apex is an LLM turn re-invoked on every SubagentStop — no hook can stop the parent from waking. What does port is the classifier + durable wake-queue + batched drain. And phantom's typed completion records (status / blocker / selfReviewScore / testResult per reference/schemas/execution.md) make the classifier stronger than firstmate's tmux tail-hash regex — we classify on structured fields, not a scraped terminal tail. Core stolen principle: benign events are absorbed only with positive evidence of progress, never by assuming silence = fine.

Wave 5 — the cards

HIGHKEEPW5-1 Wake classifier + durable queue + batched drain (~1.5–2d)

From firstmate fm-classify-lib.sh + fm-wake-lib.sh (MIT, Kun Chen). A new hooks/wake-classifier.js runs on the existing SubagentStop hook event and sorts every completion into one of two lanes:

  • ACTIONABLE — status === 'failed', blocker != null, selfReviewScore below threshold, drift detected, or last-agent-in-wave. Append the full record ref to state/<session>/.wake-queue (row shape epoch / seq / kind / key / payload), written before suppression markers advance, deduped on drain.
  • BENIGN — mid-wave, passed, no blocker. Emit a one-line stub to .triage-log only.

New scripts/lib/wake-queue.js owns append / drain / dedup. Simplify firstmate's symlink lock — phantom has one Apex, so there's no multi-watcher race to guard against. agents/apex.md gains a Phase-D prose line: "at turn start, drain .wake-queue; benign completions are pre-classified one-liners acknowledged in bulk; only actionable records get full intent / drift / blocker triage."

Fold in a 30s coalescing grace window plus an ambient liveness check at drain (firstmate's .last-watcher-beat idea). Net effect: Apex still wakes per completion (unavoidable in background mode) but a benign wake costs ~10 tokens instead of a full re-read plus reasoning pass, and simultaneous-completion bursts collapse via dedup.

SPIKEW5-2 Synchronous waves — the only path to true zero-token idle (+2–3d)

Dispatch a wave with run_in_background: false so Apex blocks once and is re-invoked once per wave, not N times. This overturns apex.md's "Never block main thread" law, so it's a spike, not a commitment.

Spike first: measure turns-per-wave under W5-1 alone versus W5-1 + synchronous short uniform waves. Keep background dispatch for long or uneven agents where blocking would waste a held turn.

HIGHKEEPW5-3 PR-body ## Validation section in phantom:wrap (small)

From the no-mistakes evidence study: no-mistakes commits domain-proof artifacts (CLI transcripts, argv/stdin captures — generic pass/fail is explicitly rejected as evidence) into .no-mistakes/evidence/<type>/<branch-slug>/ and links them at pinned SHAs from the PR body, with a collapsible per-stage pipeline audit.

Phantom's equivalents — verification.json, review-panel.json, the grill verdict — live invisibly in ~/.claude/phantom-data. The first step, with zero repo noise, is to have wrap render a distilled ## Validation section into the PR body: verify result, RPSL 4/4 (including what failed and was fixed during the panel), grill verdict, and Lens screenshots when they exist. That's ~80% of the reviewer value with no commits. Smallest item in the wave — can ship alongside any other.

MEDKEEP, GATEDW5-4 Project modes (~1–1.5d)

From firstmate fm-project-mode.sh (67 lines, awk parse, safe fallback to no-mistakes-off on typo). A new .phantom/project.json + scripts/project-mode.js consumed by wrap / close / execute:

  • no-mistakes (default) — current behavior, full verify.
  • direct-PR — skip heavy verify, still open a PR (docs / low-risk repos).
  • local-only — branch, no PR (generalizes the existing no-auto-PR-for-UI preference).

Plus a +yolo flag: Apex auto-advances ROUTINE gates only; destructive, irreversible, or security-relevant actions still hard-stop. Default OFF, and it must never override the no-auto-PR-for-UI rule.

LATERW5-5 Committed evidence artifacts (opt-in)

.phantom/evidence/{branch-slug}/ (summary.md + screenshots + transcripts) staged at push and linked from the Validation section — only behind store_in_repo, default off, exactly as no-mistakes ships it (docs default false; gh-axi opts in).

Mirror evidence.go's path-safety: relative paths only, reject .., .git, symlinks, and gitignored dirs; fall back to temp on any violation. Never for pass/fail process logs — no-mistakes explicitly rejects those as evidence; commit only real proof (Lens screenshots, repro transcripts) for UI-heavy PRs.
