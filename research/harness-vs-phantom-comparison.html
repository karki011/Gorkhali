claude-code-harness vs Phantom Skills

Research by Subash Karki — 2026-05-27 · Third-party repo analysis (not affiliated with Anthropic's Claude Code)

TL;DR

claude-code-harness (by Chachamaru, Japanese dev) is a genuinely substantial Claude Code plugin — not a wrapper. It's the most comprehensive third-party system we've found, with real architectural thinking behind spec-driven development, multi-perspective review, and worker isolation. However, Phantom already covers or exceeds most of its capabilities, and the few novel patterns worth stealing are incremental improvements, not paradigm shifts.

Worth stealing: 3-4 specific patterns. Competitive threat: Low (Japanese-only, single maintainer). Overall quality: High design, medium-high implementation.

2. Head-to-Head Comparison

2.1 Planning System

Harness

  • spec.md + Plans.md dual-document: spec is product truth, Plans is task ledger
  • Every planning action must produce a "Spec delta" or "Spec skip reason"
  • Plans.md v2 table format with Task/DoD/Depends/Status columns
  • Multi-perspective validation: Product, Architecture, Security, QA, Skeptic subagents
  • TDD tags embedded in plans ([tdd:required], [tdd:skip:reason])
  • Named Plans with manifest-based switching

Phantom

  • intent.json + plan.json with machine-checkable "Done When" predicates
  • Adversarial deliberation: Planner (Apex) ↔ Challenger (Rival), max 2 rounds
  • Adaptive routing: uncertainty × scope scoring determines ceremony level
  • Plan Checker agent validates: learnings collisions, blast radius, coverage gaps, scope creep
  • Anti-repetition loader injects past corrections into every agent prompt
  • SOLO vs SHADOWS routing — small tasks skip multi-agent overhead

Verdict: Different strengths

Harness's spec delta requirement is a genuinely good pattern — forcing explicit product decision tracking. Phantom's adversarial deliberation is more rigorous (dedicated Rival agent vs. multi-perspective prompts). Phantom's adaptive routing is more sophisticated than Harness's task-count routing. Harness's multi-perspective validation (5 viewpoints) is broader but shallower than Phantom's Rival protocol.

2.2 Execution System

Harness

  • Auto-routes by task count: 1 = solo, 2-3 = parallel, 4+ = "breezing" team mode
  • Workers operate in git worktrees for isolation
  • Lead delegates only, never writes code directly
  • Self-review gate: worker produces evidence, Lead validates before spawning Reviewer
  • Advisor protocol: structured JSON exchange, max 3 consultations per task
  • Sprint contracts generated per task
  • "Universal violations" — session-scoped gotchas injected into subsequent workers

Phantom

  • Wiring system: dependency topology → topological sort → parallel waves
  • Apex orchestrates, never implements (hook-enforced via apex-subagent-driven-law.sh)
  • Blade agents spawned with ROLE FOCUS directives, run in parallel per wave
  • Ward verifies each agent's output independently
  • Sage advisory: <100 words, no tools, max 3 calls per Blade
  • Anti-repetition block injected into every agent prompt from learnings
  • Fix loop: max 3 retries before escalation

Verdict: Phantom wins

Phantom's wiring system (explicit produce/consume mapping, topological sort into waves) is more principled than Harness's task-count routing. The hook-enforced role separation (Apex can't edit files, period) is stronger than Harness's prompt-based "Lead delegates only" rule. Harness's worktree isolation is interesting but Claude Code now has native worktree support. The self-review evidence gate pattern from Harness is worth noting though.

2.3 Review & Quality

Harness

  • Multi-mode: code, plan, scope, security, UI rubric, dual (Claude + Codex), team-debate
  • TeamAgent Debate: Spec Agent, Plans Agent, Regression Agent, Skeptic Agent — collision analysis
  • review-result.v1 JSON with explicit acceptance bar fields
  • AI residuals scanning (mockData, TODO, FIXME, skipped tests, empty assertions)
  • TDD compliance verification

Phantom

  • Gaze: weighted scoring (KISS/DRY 25%, type safety 25%, patterns 20%, re-render 15%, edge cases 15%)
  • Archer: cross-file pre-PR review — cache coherence, regressions, dead code
  • Temperature review: P0-P3 severity, state matrix for UI components
  • Sweep: post-verify simplification pass (mandatory)
  • Grill: Socratic self-challenge before shipping
  • Verdicts: APPROVED (≥7.0), NEEDS WORK (5.0-6.9), REJECTED (<5.0)

Verdict: Different strengths

Harness's TeamAgent Debate (4 agents doing collision analysis) is more structured than our review. Their review-result.v1 JSON schema with machine-checkable acceptance fields is cleaner than our score-based verdicts. However, Phantom has more specialized review agents (Gaze, Archer, Sweep — each with a distinct concern) and the mandatory Sweep simplification pass has no equivalent in Harness.

2.4 Memory & Learning

Harness

  • 3-layer: Claude auto-memory → SSOT docs (decisions.md, patterns.md) → agent memory
  • Cross-tool unified memory via harness_mem_* MCP tools
  • JSONL failover when MCP unavailable
  • "Universal violations" — session-scoped injection, no persistence
  • Resume packs for cross-session handoff

Phantom

  • 3-layer: observation hooks → domain learnings → consolidation
  • Lifecycle tags: proposed → validated:N → scope:global / stale → pruned
  • Decay: 30d stale, 60d removal candidate
  • Anti-repetition: validated:5+ auto-apply, [failed] blocked
  • Self-evolution: Tier 1 auto-promote, Tier 2-3 propose skill edits/new skills
  • Domain routing: ui, data, auth, testing, tooling, migration, shadows

Verdict: Phantom wins clearly

Phantom's learning system is significantly more sophisticated. The lifecycle with decay, validation scoring, and self-evolution creates a genuine learning loop. Harness's memory is more about persistence and cross-tool access; Phantom's is about adaptive behavior modification. The anti-repetition system (blocking failed approaches, auto-applying validated ones) has no equivalent in Harness.

2.5 Context Management

Harness

  • Skills are pure markdown — full content loaded on every invocation
  • No tiered loading system visible
  • Resume packs for session recovery
  • PreCompact hooks for state preservation

Phantom

  • 4-tier preamble system: T1 (minimal) → T4 (full orchestration)
  • Saves 40-60% tokens on simple commands
  • 10 shared context files, loaded selectively per tier
  • Pause/resume with full artifact chain
  • PreCompact consolidation hook

Verdict: Phantom wins

The tiered context loading is a major efficiency advantage. Running phantom:status (T1) loads ~25% of the context that phantom:start (T4) does. Harness loads full skill content every time. At 33+ skills, that's a lot of wasted tokens.

3. What Harness Does That We Don't

3.1 Spec Delta Requirement Novel

Every planning action must produce either a "Spec delta" (what changed in spec.md) or a "Spec skip reason" (why no change needed). This creates an audit trail of product decisions that's separate from the code.

Should we steal it? Partially. Our intent.json captures the "what" but not the "what changed from the original spec." For Jira-driven work this is less relevant (Jira has history), but for ad-hoc features it would help prevent scope drift.

3.2 Structured Review Verdicts (review-result.v1) Novel

Machine-checkable JSON with explicit fields: critical_major_zero, spec_alignment, plans_alignment, regression_safety, verification_evidence. The acceptance bar is: ALL of these must be true.

Should we steal it? Yes. Our Gaze scoring (7.0+ = approved) is more subjective. Discrete boolean fields that ALL must pass is more robust against "generous grading."

3.3 Self-Review Evidence Gate Novel

Workers produce a worker-report.v1 with self_review[].verified and evidence fields. Lead mechanically validates before spawning Reviewer. This prevents the Reviewer from wasting time on obviously incomplete work.

Should we steal it? Maybe. Our Ward already does independent verification, but a pre-screen before Ward would save tokens on failed implementations. Could be a lightweight addition to the Blade → Ward handoff.

3.4 "not_observed != absent" Principle Novel

Explicitly distinguishing "we didn't find evidence" from "evidence doesn't exist." LLMs naturally hallucinate certainty — this structural constraint prevents false negatives.

Should we steal it? Yes, as a Ward/Gaze directive. Simple addition to verification protocol: report must distinguish "checked and clean" from "not checked."

3.5 Multi-Host Adapters Interesting

Unified memory MCP works across Claude Code, Codex, and OpenCode. JSONL failover when MCP unavailable.

Should we steal it? No. We're Claude Code only by design. The JSONL failover pattern is interesting but our hook-based system already works without MCP.

3.6 Go Binary for Guardrails Interesting

Compiled binary handles deterministic checks (path validation, Plans.md parsing, file safety). Fast, no LLM overhead.

Should we steal it? No. Our JS hooks serve the same purpose and are easier to modify. The Go binary adds a build step and distribution concern.

4. What We Do That Harness Doesn't

4.1 Adversarial Deliberation (Rival Agent)

Dedicated opus agent with no tools that challenges every plan across 5 categories. Max 2 rounds. Verdict: PROCEED/REVISE/RETHINK. Harness has multi-perspective prompts but no dedicated adversarial agent.

4.2 Adaptive Cognitive Routing

Weighted uncertainty × scope scoring with learnings-based correction. Routes to minimum viable ceremony. Harness routes by task count, which is a much cruder heuristic.

4.3 Tiered Context Loading

T1-T4 system saves 40-60% tokens. Harness loads full skill content every time.

4.4 Self-Evolution Pipeline

3-tier: auto-promote validated patterns, propose skill edits, spawn new micro-skills. Harness has no self-modification capability.

4.5 Specialized Agent Roster (11 vs 4)

Each agent has exactly one concern. Hound for forensics, Lens for visual, Archer for cross-file review, Sweep for simplification. Harness overloads its 4 agents with broader responsibilities.

4.6 Hook-Enforced Disciplines

Feature branch gate and Apex edit law are enforced by actual hooks that block tool calls. Harness relies on prompt instructions for the same rules.

4.7 Wiring as Dependency Topology

Explicit produce/consume mapping, topological sort into parallel waves, integration risk detection. Harness uses Plans.md Depends column but no topology analysis.

4.8 Forensic Investigation (Hound)

7-step protocol with HTML reports, depth levels, automated suspect identification. Harness has no investigation capability — it's purely a forward-progress system.

6. Actionable Takeaways

Steal These (3 patterns)

  1. Structured review verdicts — Replace Gaze's numeric scoring with discrete boolean fields (critical_zero, spec_alignment, regression_safety, verification_evidence). All must pass. Eliminates "generous grading."
  2. "not_observed ≠ absent" directive — Add to Ward/Gaze protocol: verification reports must distinguish "checked and clean" from "not checked." Prevents false confidence.
  3. Spec delta tracking — Add optional spec_delta field to plan.json: what changed from original requirements and why. Creates product decision audit trail.

Consider These (2 patterns)

  1. Self-review evidence in Blade reports — Blade produces a brief self-review before Ward runs. Lightweight pre-screen could save Ward tokens on obvious failures.
  2. Silence policy for long runs — Explicit enumeration of what Apex should/shouldn't report during multi-agent execution. "Report state changes, not heartbeats."

Skip These

  • Go binary — Adds build/distribution complexity for marginal speed gain. JS hooks work fine.
  • Multi-host adapters — We're Claude Code only. Cross-tool portability isn't a goal.
  • Plans.md table format — Markdown tables for task management is fragile. Our JSON artifacts are more robust.
  • Named Plans with manifest switching — Over-engineering for our use case.

7. Risk Assessment

Is this repo a competitive threat?

No. Three reasons:

  1. Language barrier — Predominantly Japanese skill content. Limited to Japanese-speaking developers.
  2. Single maintainer — Bus factor of 1. Version 4.12.11 with massive surface area is unsustainable solo.
  3. Prompt-as-code fragility — The behavioral contracts (worker-report.v1, advisor-request.v1) depend entirely on LLM compliance. No structural enforcement for core workflows. When models change behavior, the whole system can break silently.

That said, the design thinking is first-rate. This developer clearly spent thousands of hours iterating on the problem. The spec-driven approach and multi-perspective validation show genuine insight into agent failure modes. Worth watching for future innovations.

8. Summary

claude-code-harness is the real deal — not a thin wrapper, not vaporware. It's the most architecturally thoughtful third-party Claude Code plugin we've seen. The spec.md/Plans.md dual-document system, structured review verdicts, and multi-perspective validation are all well-designed.

But Phantom is ahead on the dimensions that matter most for our workflow: adaptive routing, adversarial deliberation, self-evolution, context efficiency, agent specialization, and structural enforcement via hooks. The 3 patterns worth stealing are incremental improvements to an already-stronger system.

Net assessment: Respect the craft, steal the good ideas, don't worry about competition.
