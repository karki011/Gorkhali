Adaptive Cognitive Router

The old linear Phase A→B→C→D→E pipeline is replaced with adaptive routing. Human intervention scales with uncertainty, not task size. The router classifies tasks into the minimum-viable cognitive route in under 5 seconds (2 MCP calls + 2 file reads).

/team:start
→
Phase A: Context
→
Phase B: Classify
↓ route decision
DIRECT
0 human gates
Trivial tasks. Skip planning entirely. Spawn Spark, verify, done. Auto-escalates to PLAN on failure.
When: confidence ≥0.9, ≤3 files, known pattern
Spark → Verify → Done
PLAN
1 human gate
Clear scope. Deliberative planning: Planner and Challenger discuss, human approves consensus or breaks tie.
When: confidence ≥0.7, 3–10 files, clear approach
Intent → Research → Plan → Deliberate → Approve → Execute → Verify
BRAINSTORM
2 human gates
Ambiguous scope. Diverge/converge first: explore 2–3 approaches, then feed chosen direction into PLAN.
When: confidence <0.7, new domain, competing patterns
Diverge → Converge → Pick → Plan → Deliberate → Approve → Execute
FULL
3 human gates
Multi-component, cross-layer. Adds wiring mode: explicit dependency topology mapping between plan and execute.
When: 10+ files, 3+ packages, security, schema, public API
Brainstorm → Pick → Plan → Approve → Wire → Approve → Execute

Deliberation Protocol

Agents discuss among themselves. Human only approves consensus or breaks ties.

Planner (Cortex)
↔
Challenger (DA)
→
max 2 rounds
PROCEED: unified plan shown to human
REVISE: annotated concerns, human decides per point
RETHINK: two approaches side-by-side, human picks

Wiring Mode (Novel)

Dependency topology mapping between plan and execute. No other agent system has this.

For each task: what it produces and what it consumes.
Topological sort into parallel waves.
Flag risk points: merge conflicts, interface locks, cycles.
Artifact: wiring.json — dependencies, waves, riskPoints
Classification Algorithm Details

Scope Signals

  • file_count_estimate — graph blast radius
  • package_span — how many packages touched
  • layer_span — FE / BE / cross-layer

Uncertainty Signals

  • domain_novelty — no learnings matches
  • ambiguity_markers — "should we", "might", "explore"
  • competing_patterns — 2+ ways in codebase
  • missing_acceptance_criteria — vague Jira AC

Hard Overrides → FULL

  • Security-sensitive (auth, secrets, RBAC)
  • Schema migration + app code
  • Public API contract changes

Confidence → route DOWN

  • known_pattern — learnings [validated:5+]
  • clear_spec — Jira AC present
  • single_concern — one thing
  • past_routing_success — crew.md history
Learning loop: Session completes → compare planned route vs actual → SUCCESS / ESCALATED (+bias) / OVERKILL (-bias) → next similar task applies correction.

Core Disciplines (with WHY)

#DisciplineWhy
#1 Feature branch — never commit on main/develop/master Protects shared branches from half-finished work. Broken main blocks the entire team.
#2 Verification mandatory — Sentinel runs commands, reads output, confirms pass "Tests pass" without evidence is the #1 agent failure mode. Evidence-before-assertions.
#3 Anti-repetition — scan learnings/INDEX.md before any approach Without this, the same mistake repeats across sessions. Prior failures inform better plans.
#4 Devil's Advocate — every plan challenged, PROCEED/REVISE/RETHINK Catches wrong assumptions before expensive implementation. Cheap insurance.
#5 Simplify always runs — after verify pass Code grows complex during implementation. Simplify catches accidental complexity while context is fresh.
#6 Intent check — diff vs contract intent. Tests passing is not problem solved Tests verify code correctness, not feature correctness. Diff must match what user actually asked for.
#7 Smart PR — Draft PR by default for any code changes. Skip only for: on-main, no-code, user override Code should be visible to the team immediately. Decision based on what happened (changed files), not the route. See wrap.md step 14 <pr_decision>.
#8 Jira auto-transition — after push/PR Keeps project tracking in sync without manual overhead. Stakeholders see real-time progress.
#9 Learnings — every session reads and writes The knowledge system only works if fed. Reading prevents repeated mistakes; writing prevents knowledge loss.
#10 Auto-CREW trigger — 4+ files, 2+ packages, cross-cutting Large changes benefit from parallel agents. Single agent doing 10 sequential edits wastes time and context.
#11 Root cause or nothing — reproduce, trace, confirm, fix Stacking patches on a wrong hypothesis makes the real problem harder to find. Diagnosis before treatment.
#12 Parallel agents — 2+ independent files = parallel spawn Independent work should run concurrently. Sequential when parallel is possible wastes wall-clock time.
#13 Subagent-driven always — all implementation through Agent tool Keeps Cortex context clean for coordination. Implementation details in subagents don't pollute the orchestrator.
